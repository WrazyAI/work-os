# GHL Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task if native execution is selected; use superpowers:subagent-driven-development only if the user selects it. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add read-only, attributable GHL evidence to Work OS recaps, EODs, manager summaries and evidence inspection, with privacy-bounded email grounding.

**Architecture:** A location-bound PIT adapter polls into existing provider evidence and separate restricted email-content records. A single read projection separates performed actions from automation/shared/assigned/unknown context; all consumers use it, with independently enforced organization/person authorization and explicit source coverage. Durable partition checkpoints, leases and content expiry are server responsibilities, not browser timers.

**Tech Stack:** Existing Next.js 16/TypeScript, Postgres/`pg`, `node:test`/`tsx`, React/TanStack Query, existing AI model/request policy and credential encryption. Safe HTML-to-text parsing is needed; prefer a maintained parser (`htmlparser2`) over regex HTML stripping, verifying current API/types before installation and adding it only with servers stopped.

**Spec:** `docs/superpowers/specs/2026-11-06-ghl-evidence-design.md` (approved 2026-11-06).

## Global Constraints

- One shared location; all six reported identities, including shared/generic accounts; no fake Work OS people or name-only verified mappings.
- Backfill **30 calendar dates including activation day**, starting at America/New_York local midnight 29 days earlier; collect continuously every **five minutes**.
- Collect calls, email, SMS, appointments, notes, contact tasks and opportunities with documented scopes; document incomplete enumeration rather than claim full audit history.
- Outgoing email body grounding through existing AI configuration; no inbound body analysis, attachments, recordings or transcripts initially.
- Supporting excerpts at most **2,000 characters per record**, **90-day** default content retention unless an explicit organization evidence policy overrides it; full emails fetched on demand, never archived wholesale.
- Unknown/shared location-only evidence is admin-only; restricted managers retain existing person/team scope. Actor, assignee and automation are distinct.
- No GHL mutations/OAuth phase, no task auto-completion, no new check-in rows or cadence changes. Existing screenshot access and reviewed recap/submitted report contracts remain.
- Read current installed Next.js guides before writing route/UI code; read `design.md` fully before UI work. Do not install while any server uses the dependency tree.
- Execute inline by default; maintain ledger task `ac79f5bc-89fb-4d36-a702-07b8a67afe8e`. Before shared-path edits fetch Agent OS and compare touched paths by content; preserve unique platform files.
- Native Node v22.20.0 for repo checks; TestSprite uses the documented v24.20.0 installation. No deployment/database writes/live GHL reads without applicable operator gates; verify database host before writes and apply only the additive migration.

## Review Focus

1. A mapped person becomes shared/unverified while a job is running: retract personal mirrors and reject stale writes, not merely stop future attribution (Tasks 2–3).
2. A cursor expires or a job loses its lease after partial writes: restart safely without skipping/inflating evidence (Task 3).
3. An appointment is booked now for a far-future date: do not falsely report complete booking-history coverage from scheduled-date enumeration (Tasks 1, 3).
4. Email injection, HTML tracking or a forwarded quoted thread: no executable/remote content, invented claims, or unintended copied customer thread (Task 4).
5. Content expires after being cited in frozen recaps/report versions: privacy redaction must clear derived copies without regenerating employee decisions or changing task state (Tasks 4–6).
