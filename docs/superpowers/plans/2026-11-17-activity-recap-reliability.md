# Work OS Activity Recap Reliability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make sure a due Work OS recap is not silently skipped when evidence arrives late or the companion and server overlap, and verify that the newest unapproved recap is surfaced consistently.

**Architecture:** The scheduled job and companion fast path keep using the same interval engine and the existing interval row for retries. Prompt delivery checks the exact session and due instant that was processed, and the cron reports bounded outcome counts. Both companion windows read the existing owner-scoped `/latest` endpoint for notices, separately from the paginated history queue.

**Tech Stack:** TypeScript, Next.js 16, Postgres, systemd, React Query, Tauri, `node:test`/PGlite, Vitest.

**Spec:** [Server-side activity recaps design](../specs/2026-11-12-server-side-activity-recaps-design.md), plus the four approved follow-ups: bounded evidence retry, exact-slot advancement, measurable coverage and a closed-companion acceptance test, and a shared latest-recap read. Where the original spec treats all unavailable evidence as skippable, the retry rules below supersede it.

**Ledger:** `b4478954-c457-4551-bc52-59802b93952d`. Work OS baseline: `3c853902`; Agent OS comparison baseline: `cb9b0933`. Recheck both before implementation.

## Global Constraints

- Keep the five-minute timer, 24-employees default batch, four-slots-per-employee ceiling, two-hour catch-up cap, and 15-minute synthesis/goal hold backoff. Keep the 60-minute check-in and 75-minute first-follow-up defaults, including existing overrides.
- Never write `work_check_ins` or advance `last_substantive_update_at` from recap processing. Preserve consent, feature/mapping gates, workday suppressions, reviewed recaps, and null system audit actors.
- No new queue, table, migration, model client, provider integration, polling transport, or extra historical backfill. Preserve the AI policy, recap prompt, evidence selection, and attendance rules.
- Keep empty/retry rows out of the employee queue. Latest-ready (reviewed or not) governs notices; older unapproved recaps remain in Recent activity. Preserve existing post-approval copy, navigation and surface ownership.
- Additive wire changes only: the server safety fix must work with already-installed companions. Do not change versions or deploy as part of writing this plan.

## Review Focus

1. The companion advances A while cron is processing it; a newly due B is not consumed without evidence (Task 1).
2. An older installed companion POSTs `{}` after `ensure` times out; it must not consume a still-unsettled slot (Task 2).
3. A restart during a Worktivity outage does not reset the evidence deadline or expose a blank recap (Task 2).
4. One candidate's consent lookup throws; its error must be counted without blocking the rest of the batch or exposing provider data (Task 3).
5. A reviewed latest recap shares a window end with an older pending recap, or stale data arrives after an account switch; neither window announces the wrong recap (Task 4).

- [ ] **Implement bounded evidence settlement.** Usable selection wins immediately. With no usable selection, wait up to **15 minutes from `max(row.created_at, row.window_end)`** (persisted; do not renew it on retry) and retry at most once every **5 minutes** by checking `updated_at` in the common ensure module. A thrown preparation call or unresolved/failed frame processing is incomplete, not empty; after the deadline record `evidence_timeout` if still incomplete, otherwise `no_usable_frames`. Log timeout as a failed evidence outcome but allow cadence to continue; keep model synthesis failures on their existing 15-minute non-advancing backoff. Persist awaiting and terminal evidence states as `generation_status = 'unavailable'` with distinct allowlisted `failure_reason` values (`awaiting_evidence`, `no_usable_frames`, `evidence_timeout`); scope writes and use status/review/window guards so stale work cannot overwrite a ready or reviewed winner. A missing eligible row, preparing/awaiting row, synthesis failure, stale slot, lookup error, or ambiguous outcome must never advance; keep HTTP `200` with `delivered: false` for legitimate pending/mismatch cases. Cron still generates and settles pending slots; it does not claim a user notification. Old server responses without the additive fields still take the existing client fallback. Leave the server check in place regardless of client version.
