# Floating Otto Employee / Administration View Switch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for the main implementation. Execute the tightly coupled tasks inline; delegate only Task 5, explicitly to `openai/gpt-6.1-sol#high`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Administrators switch both companion windows between Employee and Administration from the mascot, keep the matching real conversation, and see Otto's Administration outfit.

**Architecture:** Main owns the effective workspace, monotonically fenced presentation snapshots, and admin conversation identity. Avatar adopts that authority through the existing event adapter; it renders the existing `AdminOttoChat`, not another admin engine. A small ids-only conversation coordination adapter protects cross-window first sends and New chat; the existing server remains responsible for authorization, history, previews, confirmation, and durable discard. Configured mascot renderers gain accessories, with the collapsed pet alone owning the one-shot transition.

**Tech Stack:** React 19, TypeScript, Vite/Vitest, existing Tauri v2 events, local SVG/CSS, rendered browser/native checks. No dependency installation is planned.

**Spec:** `docs/superpowers/specs/2026-11-05-mascot-view-switch-design.md`; canonical blueprint: `design.md`, especially §§4.2, 7.2–7.4, 10, 13, 14, 16.2.

## Global Constraints

- No new Tauri command, Rust change, ACL permission, server API, or alternative authorization path. Use `src/tauriEvents.ts`, not direct event imports in new adapters.
- Main is the workspace authority. A successful request result acknowledges an action; only an adopted owner snapshot changes Avatar's visible mode. No optimistic local mode toggle.
- Preserve admin-only, organization/session-bound reads, preview/confirm, per-item receipts, provenance, and authoritative status checks for indeterminate mutations. Never put employee decisions in admin chat.
- Preserve conversation identity, prepared previews, each window's own draft, and retry request identity across view switches/collapse/context recovery. New chat is a durable discard, not a cosmetic reset. Account/session replacement clears local retained state; view switches do not discard server work.
- No conversation text, drafts, record bodies, credentials, lease tokens, or provider data on new events. Only validated scopes, epochs, revisions, opaque ids, capability/status fields, and the explicitly allowed same-app record URL. Navigation is the one URL-bearing exception, not a general message channel.
- Identity/art stay behind `MASCOT` in `desktop/work-os-companion/src/mascot.ts`, `MascotMark`, and `MascotPet`. No new raster asset or second mascot renderer.
- One-shot outfit motion, no replay on mount/expand/collapse/heartbeat; final static state under reduced motion. Header marks are static, not a second dressing animation.
- Desktop switch art is 36px; its interactive target is at least 40px at narrow/touch widths. Keep New chat, close/collapse, and all tabs reachable.

### Spec conflict resolutions (preserve the approved product)

1. **Epochs on requests:** extend the spec's `{requestId, scope, mode}` with `epoch`. Scope alone does not reject an old Admin→Employee request after Admin→Employee→Admin. Results echo the initiating scope/epoch; do not replace it with the destination scope.
2. **Unknown/admin-unready boot:** show a neutral connecting surface until identity/view authority is known. A known employee keeps existing Employee behavior. A known admin without a view snapshot must not default to Employee chat; a selected Administration loading/failed snapshot renders Administration unavailable. Failure resolves to the same effective Administration branch as bootstrap.
3. **Conversation synchronization:** `OTTO_CONVERSATION_EVENT` is an owner-committed identity snapshot with generation/revision, not a bidirectional unsequenced null/id write. Requests and acknowledgements are ids-only companions to it (Task 2). This is needed to preserve the spec's New chat and pending-first-send guarantees without changing the server API.
4. **Loss vs cancellation:** switching cancels local presentation and retains draft/idempotency key; it does **not** discard the server request or its preview. An already accepted confirmation may finish on the server; returning rehydrates/status-checks it. Never claim abort rolled back a write.
5. **Motion:** delete the former instruction to animate header marks. Only a still-mounted collapsed `MascotPet` animates a runtime mode change. A change while expanded appears dressed immediately and must not replay when collapsed later.
6. **Release concurrency:** another outcome landing first does not automatically make this feature wait. The latest **published snapshot**, not which agent was fifth chronologically, determines pending outcomes; release all pending outcomes in the eligible snapshot. Preparation and publication are separate gates.
