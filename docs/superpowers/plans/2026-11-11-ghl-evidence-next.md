# GHL Evidence Next-Phase Implementation Plan

> **For agentic workers:** Use `executing-plans` inline unless the user explicitly selects delegation. This is a handoff, not authorization to implement or deploy. Check boxes as work completes.

**Goal:** Make the existing GHL evidence visible, correctly attributed, fresh, and traceable in manager summaries, Admin Otto, recaps, EODs, and SOD planning without manufacturing work or completion.

**Architecture:** Reuse normalized GHL events, verified-person mirrors, per-category sync state and existing authorized consumers. Present GHL source metrics as a breakdown of existing totals, never an additional total; separate organization-only context from employee-performed occurrences. Keep Otto reads typed and server-authorized and treat email-derived text as expiring evidence, not durable unbounded chat context.

**Tech stack:** Next.js 16, TypeScript, PostgreSQL, React, Tauri companion, node:test/tsx, existing TestSprite projects.

**Spec:** `docs/superpowers/specs/2026-11-06-ghl-evidence-design.md`; prior plan `docs/superpowers/plans/2026-11-06-ghl-evidence.md`; operations `docs/ghl-evidence-operations.md`. Later verified state in this document supersedes stale pilot/key statements in those documents.
